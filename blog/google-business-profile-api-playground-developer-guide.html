Google Business Profile API Playground: Test, Authenticate, and Scale Local SEO APIs Without Backend Headaches

Say goodbye to broken OAuth tokens, confusing pagination loops, and fragmented endpoints. Discover how VitableTech's live playground and TypeScript SDK turn weeks of API wrestling into minutes of clean execution.

If you have ever attempted to integrate the Google Business Profile (GBP) API (formerly Google My Business) into a production application, you know firsthand that it can feel like navigating an obstacle course in the dark.

Between multi-part OAuth 2.0 consent screens, access tokens expiring after a strict 60 minutes, pagination requiring manual nextPageToken cursor handshakes, and an ecosystem fragmented across four completely separate Google Cloud APIs, what should be an afternoon feature frequently devolves into weeks of debugging.

At VitableTech, our engineering team manages massive multi-location local SEO infrastructures, review management pipelines, and automated business analytics for enterprise clients and digital marketing agencies across the globe. We grew frustrated with setting up boilerplate backend servers just to verify an OAuth redirect or test a single metric endpoint.

That is why we built and published the VitableTech Google Business Profile API Playground and open-sourced our battle-hardened @vitabletech/gbp-sdk.

Why Google Business Profile API Development is Unforgiving
  • 1.
    Fragmented Cloud Endpoints: Business Information, Reviews, Performance Metrics, and Verifications live under distinct hostnames (mybusinessbusinessinformation.googleapis.com, businessprofileperformance.googleapis.com, etc.) with incompatible request structures.
  • 2.
    The 60-Minute Token Cliff: Google access tokens expire on the hour. Without strict concurrency-safe refresh token management, high-volume production jobs throw cascading 401 Unauthorized errors.
  • 3.
    Deprecation of Legacy Insights: Google sunset the legacy GMB Insights API. The modern Performance API v1 uses entirely new daily time-series metrics and monthly search keyword impression schemas that lack thorough documentation.
  • 4.
    Cryptic Pagination Loops: Multi-location enterprises with 1,000+ branch locations must handle recursive cursor requests without hitting Google's sensitive rate limits.

Meet the Solution: VitableTech GBP API Playground

The GBP API Playground is a zero-setup, web-based developer environment hosted at https://gbp-playground.vitabletech.in/. It allows any engineer or technical marketer to test Google Business Profile integrations in seconds using their own Google Cloud Console credentials.

Bring Your Own Credentials (BYOC)

Paste your Google Client ID & Secret to authenticate directly against your company's Google Cloud project. No pre-seeded demo data locks you in.

Zero-Storage Security Policy

Your Client Secret, access tokens, and refresh tokens reside exclusively in client-side memory and ephemeral browser session storage. Nothing is stored on our database.

Interactive Swagger UI Docs

Jump into /api-docs/ to inspect full OpenAPI 3.0 schemas, test parameters, and examine actual raw JSON payloads.

Performance API v1 Ready

Query daily impressions, direction requests, phone calls, and monthly search keyword breakdowns without guessing JSON request envelopes.

Step-by-Step: How to Test GBP APIs in 3 Minutes

Here is the exact step-by-step flow to authenticate and execute your first Google Business Profile API call using the playground:

Step 1

Create an OAuth 2.0 Web Application in Google Cloud

Navigate to the Google Cloud Console → APIs & Services → Credentials. Create an OAuth 2.0 Client ID and choose Web application as the application type.

Step 2

Whitelist the Mandatory Authorized Redirect URI

Under Authorized redirect URIs in Google Cloud Console, add the following exact URL:

https://gbp-playground.vitabletech.in/auth/google/callback

Tip: The playground provides a 1-click "Copy URI" button right at the top of the interface for convenience.

Step 3

Authenticate with Google

Return to gbp-playground.vitabletech.in, enter your Client ID and Client Secret, click Save Credentials, and hit Login with Google Business Profile.

Step 4

Execute Real Endpoints via Swagger UI

Once authenticated, click Open Swagger API Docs. You can immediately call:

  • GET /accounts – List all managed merchant business accounts.
  • GET /locations – Paginate through all active store locations.
  • GET /reviews – Read customer reviews, ratings, and comment replies.
  • POST /performance/daily-metrics – Query daily impressions and customer interaction time series.
  • POST /performance/search-keywords – Inspect local search query impressions for organic ranking audits.

The Engine Under the Hood: @vitabletech/gbp-sdk

The playground is built on top of our official open-source package, @vitabletech/gbp-sdk (v1.3.0). While the playground lets you experiment visually in the browser, the SDK powers your actual backend microservices, cron jobs, and webhooks.

1. Installing the SDK 

npm install @vitabletech/gbp-sdk
# or using pnpm
pnpm add @vitabletech/gbp-sdk

2. Fetching Multi-Location Accounts with Auto-Pagination

Instead of manually tracking pageToken query parameters and chaining promises, call listAll(): 

import { GBPClient } from '@vitabletech/gbp-sdk';

const client = new GBPClient({
  clientId: process.env.GOOGLE_CLIENT_ID!,
  clientSecret: process.env.GOOGLE_CLIENT_SECRET!,
  redirectUri: 'https://your-domain.com/auth/callback',
});

// Pass the refresh token retrieved during OAuth
client.setRefreshToken(process.env.STORED_REFRESH_TOKEN!);

async function syncBusinessLocations() {
  // 1. Fetch all accounts attached to the authenticated profile
  const accounts = await client.accounts.list();
  const primaryAccount = accounts[0];

  // 2. Fetch EVERY location with automatic recursive pagination
  const allLocations = await client.locations.listAll({
    parent: primaryAccount.name,
    readMask: 'name,title,storeCode,storefrontAddress,phoneNumbers,websiteUri',
  });

  console.log(`Successfully fetched ${allLocations.length} locations across your organization!`);
  return allLocations;
}

3. Querying Performance API v1 Metrics (Daily Time-Series & Search Keywords)

The modern Performance API v1 is notorious for its strict date formats and multi-layered request objects. Here is how easy it is with @vitabletech/gbp-sdk: 

// Query Daily Metrics (Website clicks, Call button clicks, Directions)
const dailyMetrics = await client.performance.getDailyMetricsTimeSeries({
  name: 'locations/1234567890123456789',
  dailyMetric: 'BUSINESS_IMPRESSIONS_DESKTOP_MAPS',
  dailyRange: {
    startDate: { year: 2026, month: 10, day: 1 },
    endDate: { year: 2026, month: 10, day: 31 },
  },
});

// Query Top Search Keywords driving local discovery
const topKeywords = await client.performance.listSearchKeywordsImpressionsMonthly({
  parent: 'locations/1234567890123456789',
  monthRange: {
    startMonth: { year: 2026, month: 8 },
    endMonth: { year: 2026, month: 10 },
  },
  pageSize: 50,
});

for (const keyword of topKeywords.searchKeywordsCounts || []) {
  console.log(`Keyword: "${keyword.searchKeyword}" -> Impressions: ${keyword.insightsValue?.value}`);
}

Frequently Asked Questions (Developer & Agency FAQs)

What is the VitableTech GBP Playground and do I have to pay for it?

The VitableTech GBP Playground is 100% free and open to all developers, technical marketers, and product managers. You bring your own Google Cloud OAuth credentials and execute calls directly against your own accounts with zero fees or tier limits.

Are my Google OAuth credentials or tokens saved on your servers?

No. We maintain a strict zero-retention security policy. Your Client ID, Client Secret, access tokens, and refresh tokens exist purely inside your browser's local session memory. Nothing is ever written to any database, file system, or analytical tracking tool on our servers.

Which Google Cloud APIs must be enabled for full playground functionality?

To unlock all Swagger endpoints, enable the following in your Google Cloud Console:

  • Google Business Profile Business Information API
  • Business Profile Performance API (for daily time-series & keyword impressions)
  • My Business Account Management API
  • My Business Verifications API

How does the playground and SDK handle Google's 60-minute token expiration?

Google access tokens expire after exactly 3600 seconds (1 hour). The underlying @vitabletech/gbp-sdk includes an internal thread-safe token manager that automatically exchanges your refresh token for a brand new access token right before expiration, eliminating interrupted jobs.

Can I deploy @vitabletech/gbp-sdk to serverless platforms (Netlify, AWS Lambda, Cloudflare)?

Yes. The SDK was purposefully built with lightweight, zero-bloat dependencies. It runs smoothly on Node.js 18+, Netlify Serverless Functions, AWS Lambda, Google Cloud Run, and containerized Docker environments.

What is the difference between legacy GMB Insights and Performance API v1?

Google completely deprecated the old reportLocationInsights endpoint. The modern Business Profile Performance API v1 separates engagement metrics into daily time-series counts (calls, website clicks, message conversations, booking clicks) and aggregates search keywords into monthly impression rankings. Our SDK and playground fully support this modern v1 format.
